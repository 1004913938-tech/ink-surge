# 知音服务器：店主使用说明

有了知音服务器，朋友**不用自己注册 Deepgram**，向你买一个「授权码」就能用知音字幕：

```
朋友在字幕页面点「申请」→ 按你的付款说明付款 → 你在后台「确认收款并发码」→ 把消息复制到微信发给朋友
朋友粘贴授权码 → 开始 → 声音经过你的服务器转给 Deepgram（用你的 Key）→ 服务器按分钟计时，用完自动停止
```

- 你的 Deepgram Key 只放在服务器上，朋友看不到。
- 每个授权码可以限制**分钟数**、**有效天数**，或两个都限（先到为准）。
- 服务器放在 Cloudflare 上，免费版就能先试；**收钱之前请升级到 $5/月的付费版**（见第 9 节）。
- 第一次设置约 20–30 分钟，只需要点网页，不用装任何软件。以后日常只用「店主后台」网页。

> 下面的网页按钮名称是写这份说明时的样子，网站改版后可能略有不同，找意思相近的按钮即可。
> Cloudflare 和 GitHub 的界面是英文的，下面写的是英文按钮名。

## 第一次设置

### 1. 注册 Cloudflare（免费，不用绑卡）

1. 打开 https://dash.cloudflare.com/sign-up
2. 填邮箱和密码 → **Sign up**。
3. 去邮箱点验证链接。
4. 如果它让你「添加网站 / 域名」，直接跳过，不需要域名。

### 2. 复制 Account ID（账户 ID）

1. 登录后打开 https://dash.cloudflare.com/?to=/:account/workers-and-pages
2. 在页面右边的 **Account Details** 里找到 **Account ID**，点旁边的复制按钮。
   找不到的话：按 **Ctrl + K**（Mac 按 **Cmd + K**），输入 `account id`，选 **Copy account ID**。
3. 先粘贴到记事本里，第 5 步要用。

### 3. 创建 API Token（让 GitHub 能帮你部署）

1. 打开 https://dash.cloudflare.com/profile/api-tokens
2. 点 **Create Token**。
3. 在模板列表里找到 **Edit Cloudflare Workers**，点右边的 **Use template**。
4. **Account Resources**：选 **Include** → 你的账户。
   **Zone Resources**：选 **Include** → **All zones**。
5. 拉到最下面点 **Continue to summary** → **Create Token**。
6. 复制显示出来的 Token，粘贴到记事本。**它只显示这一次**，关掉页面就看不到了（丢了就再建一个）。

### 4. 在 Deepgram 建一个服务器专用 Key

1. 登录 https://console.deepgram.com
2. 左上角确认选的是你的**第一个（主）项目**。同时能连几路按项目计算，后来新建的项目可能只允许 1 路。
3. 左边菜单 **API Keys** → **Create a New API Key**。
4. 名字填 `zhiyin-server`，权限用默认的 **Member**，有效期选永不过期 → 创建。
5. 复制 Key，粘贴到记事本。
6. 顺便看一下 **Billing**（余额）大于 0。

### 5. 在 GitHub 填 4 个 Secrets（保密设置）

1. 打开 https://github.com/1004913938-tech/ink-surge/settings/secrets/actions
   （也可以：仓库页面 → 上方 **Settings** → 左边 **Secrets and variables** → **Actions**）
2. 点绿色的 **New repository secret**。**Name** 填名字，**Secret** 填值，点 **Add secret**。一共做 4 次：

| Name（照抄，全大写） | Secret（值） |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | 第 3 步复制的 Token |
| `CLOUDFLARE_ACCOUNT_ID` | 第 2 步复制的 Account ID |
| `DEEPGRAM_API_KEY` | 第 4 步复制的 Deepgram Key |
| `ADMIN_PASSWORD` | 你自己想的**后台密码，至少 16 位**。最好是 4 个以上随便挑的词或拼音连在一起（例如 `qingtian-xigua-shubao-dengpao`），不要用生日、电话这类别人猜得到的；中文也可以。记在你的密码本里 |

- 填错了：在列表里点那个 secret 右边的铅笔图标重新填（GitHub 不会再显示原来的值，这是正常的）。
- 填完 secrets 不会自动部署，要做下一步。

### 6. 部署服务器（点一次按钮）

1. 打开仓库页面 → 上方 **Actions** → 左边选 **Deploy ZhiYin server (Cloudflare Worker)**。
2. 右边点 **Run workflow** → 分支保持 `main` → 点绿色的 **Run workflow**。
3. 等 3–5 分钟，出现绿色对勾 ✓ 后，点进这次运行，往下看 **Summary**（摘要）：
   - **服务器**：`https://zhiyin-api.xxxx.workers.dev`
   - **店主后台**：`https://zhiyin-api.xxxx.workers.dev/admin` ← **把这个地址加入浏览器书签**
4. 这次运行最后会自动重新发布字幕页面。再等 2–3 分钟，打开 https://1004913938-tech.github.io/ink-surge/zhiyin/ ，
   第 1 步出现「用授权码（向店主购买）」就说明全部通了。

没成功时：

| 看到什么 | 怎么办 |
| --- | --- |
| 绿色 ✓，但 Summary 写「知音服务器未部署：缺少 secrets: …」 | 按提示补上缺的那个 secret（名字要一模一样），再 Run workflow |
| 红色 ✗，红在 **Check repository secrets** | `ADMIN_PASSWORD` 不到 16 位，改长一点再 Run workflow |
| 红色 ✗，红在 **Check repository secrets** 或 **Ensure workers.dev subdomain** | 点进这次运行，**Summary** 和红色错误里会用中文写明是哪个 secret 不对（`CLOUDFLARE_API_TOKEN` 无效或权限不够 / `CLOUDFLARE_ACCOUNT_ID` 不对 / 两者不属于同一个账户）。按提示重新复制、更新那个 secret，再 Run workflow。复制时多带的空格、换行，或者把整个网址当成 Account ID 粘进去，都会自动纠正，不用担心 |
| 红色 ✗，红在 **Deploy Worker** | 再点一次 **Re-run jobs**（第一次部署偶尔要跑两次）；还是红就把这一步的错误截图发给懂技术的朋友 |
| Summary 有地址，但打开后台显示打不开 | 新地址第一次要几分钟才生效，过 5–10 分钟再试 |
| 字幕页面没有「用授权码」选项 | Actions → **Deploy GitHub Pages** → **Run workflow**，等它变绿后刷新字幕页面 |

### 7. 打开后台，填付款方式和套餐

1. 打开书签里的 `…workers.dev/admin`，输入 `ADMIN_PASSWORD` → **登录**。
   密码只保存在这个浏览器标签页里，关掉标签页要重新输入。输错 10 次会锁 15 分钟。
   如果短时间内各处一共输错很多次（可能有人在猜密码），整个后台会锁 15 分钟；反复出现时，在 GitHub 把 `ADMIN_PASSWORD` 换成一个更长的新密码并重新部署（第 6 步），换完立刻解锁。
2. 点 **设置** 标签：
   - **付款说明**：朋友提交申请后会看到这段话。写清楚收款方式，并提醒在付款备注里写申请编号。例如：
     ```
     微信转账给 xxx（微信号 xxx）
     支付宝：xxx
     付款时请在备注里写申请编号 R…
     ```
   - **套餐**：点「＋ 添加套餐」，每行填 **套餐名称 / 分钟数 / 有效天数 / 价格**。
     - 分钟数留空 = 不限分钟；天数留空 = 长期有效；两个都填时先到为准。最多 10 个。
     - 价格就是给朋友看的文字，例如 `¥50`。
     - 例子：`试用 1 小时 / 60 / 7 / ¥10`，`包月 10 小时 / 600 / 30 / ¥50`。
   - **开放网页申请**：打勾 = 朋友可以在字幕页面申请；不打勾 = 只能你「手动新建」发码。
   - **同时在线上限（1–60）**：默认 25，一般不用改。
   - **Deepgram 每分钟成本（美元，仅用于估算）**：默认 0.0077，只用来在「用户」里估算费用。
3. 点 **保存设置**。朋友那边最多 30 秒后就能看到新套餐（让他们刷新页面）。

### 8. 自己先试一次（5 分钟）

1. **用户** → **＋ 手动新建** → 称呼填「测试」，分钟数填 `2`，天数留空 → 发码 → **复制消息**。
2. 用电脑版 Chrome 打开字幕页面 → 第 1 步选「用授权码」→ 粘贴（整条消息也可以，页面会自动只留下授权码）→ 开始，放一段英文视频。
3. 大约 2 分钟时字幕应该自动停止，并显示「授权码的时长已用完或已到期，请联系店主续费」。
4. 再给这个码 **充值** 5 分钟，在两个标签页里同时用这个码开始：先开的那个应该停止，显示「已在另一个页面或设备上开始使用」。
5. 试完把这个测试码 **删除**。

## 日常使用

### 确认收款并发码

1. 朋友在字幕页面点「还没有授权码？申请」，提交后会拿到一个**申请编号**（R 开头，例如 `R7K3QM`），并看到你的付款说明。
2. 你在后台 **待确认** 里看到这条申请：申请编号、时间、称呼、联系方式、套餐、备注。
3. 在微信 / 支付宝里核对：**付款备注里的申请编号**和金额对得上。
4. 点 **确认收款并发码**：分钟数和天数已经按套餐填好（可以改），备注写收款情况（例如 `微信 ¥50`，只有你能看到）→ 确认。
5. 弹出授权码，**只显示这一次**。点 **复制消息**，到微信粘贴发给朋友。消息里已经有授权码、额度、有效期和字幕页面地址。
   朋友把整条消息粘贴到授权码框里也可以用。
   - 有效天数按雅加达时间的整天算：今天发 30 天，就到第 30 天的 23:59（WIB）为止，和消息里写的「有效期至」那天一致。
   - 弹出授权码后如果提示「网络连接失败」，授权码已经生成好了，照样复制发出去，再点右上角「刷新」。
6. 没收到钱或不认识这个人：点 **拒绝**（朋友不会收到通知；如果对方已经付了钱，记得退款）。
7. 突然出现一大堆垃圾申请：点 **全部拒绝**（只拒绝你当时看到的那些）。网页申请每小时一共最多 30 个，同一个网络每小时最多 5 个。

不经过网页申请、直接给某个人发码：**用户** → **＋ 手动新建**（可以选套餐快速填写）。

### 续费、停用、换码、删除（「用户」标签）

表格里有：已用 / 总额、剩余、到期时间、最近使用、绿点 = 正在使用、本月用了多少分钟和大约多少美元。
**时间都是雅加达时间（WIB），比北京时间晚 1 小时。**

| 想做什么 | 点哪里 | 说明 |
| --- | --- | --- |
| 续费 / 加时长 | **充值** → 填增加分钟、增加天数、备注 | 朋友正在用时立刻生效，不会断开。已过期的码从今天起算天数。分钟数填负数可以扣回（用于改错），最多扣到总额为 0；扣多了会提示，不会悄悄改 |
| 暂停某人 | **停用** | 正在用的会立刻断开，朋友看到「授权码无效或已停用」。以后可以点 **启用** 恢复 |
| 朋友说授权码泄露了 / 想换码 | **重新发码** | 旧码立刻作废，剩余额度和有效期不变。把新消息复制发给朋友 |
| 查使用情况 | **记录** | 每次使用的开始时间、时长、怎么结束的；以及发码、充值的账目 |
| 不再给某人服务 | **删除** | 抹掉称呼和联系方式并停用，使用记录保留用于对账。**不能恢复** |

- 后台**看不到授权码原文**（服务器只保存加密后的指纹）。朋友弄丢了授权码，就给他 **重新发码**。
- 一个授权码同时只能在一个页面用，后开的会把先开的挤掉。这样一个码很难分给多人用。

### 后台顶部出现红色提示「⚠ 识别服务异常」

说明你的 Deepgram 账户最近拒绝了连接，朋友那边会显示「识别服务暂停，请联系店主」，页面每分钟自动重试。

- **Deepgram 余额不足**：登录 https://console.deepgram.com 充值。充值后朋友会自动恢复。
- **Deepgram Key 被拒**：Key 可能被删了。在 Deepgram 新建一个 Key → GitHub 里更新 `DEEPGRAM_API_KEY` secret → Actions → **Deploy ZhiYin server** → **Run workflow**。
- **同时连接太多（429）**：在 **设置** 里把「同时在线上限」调低一点。

只要之后有一次连接成功，红色提示就会自动消失。

### 什么时候不要更新服务器

每次部署（自己点 Run workflow，或者仓库里 `livecaption/server` 有改动）都会让正在用的朋友断开 1–3 秒再自动重连。
部署前看一眼后台顶部的「在线」人数，尽量在没人开会时部署。

## 9. 收钱之前一定要做

1. **把 Cloudflare 升级到 Workers Paid（$5/月）**
   - 免费版每天有请求次数上限。按估算，免费版每天大约能撑 **4 到 77 小时**的总使用时长（这个范围不确定）。
     超过后当天所有朋友都连不上，要等到**北京时间早上 8 点（雅加达时间 7 点）**才恢复。
   - 付费版每月 $5，大约包含每月 1000 小时的总使用时长，超出部分很便宜。
   - 升级：Cloudflare 控制台 → 左边 **Workers & Pages** → **Plans**（或页面上的 **Upgrade**）→ 选 **Workers Paid** → 按提示绑卡。
2. **自己再读一遍 Deepgram 的服务条款**：https://deepgram.com/terms （第 2 节，使用限制）。
   用你的 Deepgram 账户给别人提供识别服务、向别人收钱，是否符合条款由你自己负责。拿不准就先只给熟人用，或者写邮件问 Deepgram。
   任何时候你都可以在后台停用任何人的授权码。
3. **定价要高于成本**
   - Deepgram：约 $0.0077/分钟，约 $0.46/小时（打开「区分说话人」还要另加；以 Deepgram 官网价格为准）。
     朋友用的时间**包括没人说话的时间**（Deepgram 也是这样收费的）。
   - 有人用程序把录音飞快地塞给服务器（比正常说话快）时，服务器按 Deepgram 实际收到的录音时长扣他的时间，并马上断开；「记录」里显示「发送过快」。正常用字幕页面不会遇到。
   - Cloudflare：付费版 $5/月。
4. （可选，请懂技术的朋友帮忙看）第一次正式使用 10 分钟后：
   Cloudflare 控制台 → **Workers & Pages** → `zhiyin-api` → **Metrics** 看请求数和 CPU 时间；
   Deepgram 控制台 → **Usage**，按标签 `u<用户编号>` 筛选，对比后台「记录」里的时长。

## 安全须知

- `ADMIN_PASSWORD` 不要告诉任何人。忘了就在 GitHub 更新这个 secret，再 Run workflow。
- 后台地址（`…workers.dev/admin`）不要发给朋友。朋友只需要字幕页面地址。
- 朋友的授权码保存在朋友自己的浏览器里；被别人拿到了就给他 **重新发码**。
- 服务器**不保存录音，也不保存字幕文字**，只记录每次使用的时长和流量，用于计费和对账。
  申请里的称呼和联系方式在 **删除** 时会被抹掉；处理过的申请 90 天后自动清除。

## 常见问题

| 问题 | 回答 |
| --- | --- |
| 改了套餐，朋友看不到 | 最多等 30 秒，让朋友刷新字幕页面 |
| 不想再接受网页申请 | **设置** → 取消「开放网页申请」→ 保存。之后只能「手动新建」 |
| 朋友在中国大陆打不开 | `workers.dev` 和 `github.io` 在大陆能不能稳定访问还没有验证过。需要的话可以换成自己的域名（需要懂技术的人帮忙：仓库变量 `ZHIYIN_SERVER_URL`，并把字幕页面所在网址加进 `wrangler.jsonc` 的 `ALLOWED_ORIGINS`） |
| 朋友想用自己的 Deepgram Key | 字幕页面第 1 步选「用自己的 Deepgram Key」即可，不经过你的服务器，也不计你的时长 |
| 想换 Deepgram Key / 后台密码 | GitHub 里更新对应的 secret → Actions → **Deploy ZhiYin server** → **Run workflow** |

## 开发者

- 代码：`src/index.ts`（Worker 入口：路由、CORS、后台页面 CSP）、`src/hub.ts`（唯一的 Durable Object：SQLite 数据库 + 所有转发连接）、
  `src/session.ts`（一路转发和计时）、`src/lib.ts`（纯函数）、`src/admin.html`（店主后台）。
- 本地运行（不需要 Cloudflare 或 Deepgram 账户）：
  ```
  cd livecaption/server && npm ci
  npm run typecheck
  npm test                      # 单测 + 本地端到端（wrangler dev + 模拟 Deepgram）
  LC_DEPS=<含 playwright 的目录> npm run test:fullchain   # 真页面（Chromium）→ wrangler dev → 模拟 Deepgram
  ```
  本地开发要用 `npx wrangler dev` 时，在本目录建 `.dev.vars`（已在 .gitignore 里）写 `DEEPGRAM_API_KEY=…` 和 `ADMIN_PASSWORD=…`；测试脚本只用临时文件里的假值，不读也不改你的 `.dev.vars`。
- 计时与限流（`src/session.ts`、`src/lib.ts`）：按 max(墙钟时间, Deepgram 回报的音频时间) 计时；上传超过实时太多（字节、消息数，
  或音频进度比墙钟快 10 秒以上）时以 4413 断开；客户端离开后最多等 3 秒拿 Deepgram 的 Metadata 再结账；写不进用量时断开（fail closed）。
  按地址的限流以 IPv6 /64 为单位；另有全局的后台密码锁（存进 SQLite，换密码即解除）、全局申请上限（`REG_PER_HOUR`，默认 30，测试用）、
  每个授权码每分钟 20 次连接。
- 部署：`.github/workflows/zhiyin-server.yml`（PR 只跑测试；main 分支有 4 个 secrets 时才部署）。
  `.github/workflows/pages.yml` 构建时自动查到服务器地址，填进字幕页面的 `<meta name="zhiyin-server">`；还没有部署服务器时留空（页面不显示授权码模式）；Cloudflare 查询失败时沿用线上页面已有的地址并给出警告，连线上页面也读不到时这次构建失败（线上页面保持不变）。
